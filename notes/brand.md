# RAINMAN brand

Source sheet: `notes/brand/RAINMAN_Brand.pdf` (Josh, 2026-10-08).
Code source of truth: **`scripts/brand.py`** — themes, mascot, switch, league tags. Nothing else defines a brand colour.
Living reference: **`dashboard/brand.html`** (rebuild with `python3 scripts/build_brand_assets.py`).

Tagline **Count the edge.** · Voice **Number first. Work second. No locks, no promises.**

## The three visibility options

| | key | background | text | accent | use |
|---|---|---|---|---|---|
| **Dark** | `dark` | `#000` | `#e6e6e8` | amber `#e8b339` | the default, and the site exactly as it was before themes existed |
| **Light** | `light` | paper `#f3efe6` | navy `#14213d` | orange `#e8590c` | daylight, printing, screens behind glass |
| **Rain** | `rain` | night `#0b1220` | frost `#e6f1ff` | mint `#19e3b1` | long sessions; dark without the pure-black glare |

The theme lives on `<html data-theme="...">` and is remembered in `localStorage["rm-theme"]`.
Every page header carries a **D / L / R** switch (`brand.theme_switch_html()`); the active one fills with the accent.
`brand.THEME_BOOT` runs before first paint, so there is no flash of the wrong theme, and it also carries the favicon.

### Tokens

Full values are in `scripts/brand.py → THEMES`. The names every page uses:

```
--bg --panel --s2 --s3        surfaces, lightest last
--edge --edge2                hairlines
--txt --dim --dim2            text, secondary, decorative-only
--accent --accent-text        the brand colour; accent-text is the readable version on a surface
--on-accent                   text drawn on top of an accent fill
--amber --green --red --cyan --violet    semantic
--mark --mark-shade           the mascot's body and its visor
--lg-nfl --lg-cfb --lg-nba --lg-wnba --lg-nhl   one tag colour per league, darker on paper
```

Older pages used shorter names (`--p --e --fg --acc --g --r --b --mute --blue`). `brand.alias_css('app' | 'alt')`
points those at the canonical names, so a page keeps its own CSS and still themes.

### How dark is kept byte-identical

Dark is not allowed to drift. The dashboards still carry hundreds of colour literals from before themes existed, so
instead of rewriting them `brand.themed_css()` turns every literal into `var(--kN, ORIGINAL)` and emits override
blocks for light and rain only. Dark defines none of those variables, so each one falls back to the original
literal and **cannot** change. Light and rain are generated by role: greys ride that theme's background-to-text
ramp, saturated colours snap to its nearest semantic token, and alpha is preserved.

If you add a colour to a page, prefer a token. A literal is fine — it will be mapped automatically on the next build.

## The mascot

A rain cloud in a visor, five drips hanging under it, and a tally stroke counted across them. **Each drip is a tally.**
Fills are `var(--mark)`, `var(--mark-shade)` and `var(--accent)` — it recolours itself with the theme, never hard-coded.

`brand.mascot(state, size)` · standalone files in `dashboard/assets/mascot/<state>.svg`

| state | when to use it |
|---|---|
| `counting` | the default. The header mark on every page. |
| `edge` | an edge cleared the threshold — a tier-A play, a filled arbitrage. Never decoration. |
| `noplay` | nothing qualifies: an empty board, a filtered view with no rows, a league with no slate. |
| `loading1`–`loading4` | load progress; each drip fills in turn and the tally strikes at four. |
| `error` | a pull failed or a number cannot be trusted. Always name what broke beside it. |
| `live` | prices or scores are moving. The dot pulses; nothing else on the site animates. |

Other marks: `brand.lockup(size, stacked=False)` (mascot + wordmark), `brand.app_icon(size, theme)` (rounded square,
accent field, mark knocked out) — written to `dashboard/assets/mascot/icon-<theme>.svg` and used as the favicon.

## Adding a theme or changing one

1. Edit `THEMES` in `scripts/brand.py` (and `LEAGUE_TAG` if the new theme needs its own tags).
2. Add the key to `ORDER` and `LABEL`. The switch, the boot script and every page pick it up with no other change.
3. `python3 scripts/build_brand_assets.py` then rebuild the pages (`scripts/refresh.py`, `scripts/build_landing.py`,
   `scripts/build_arb.py`, `scripts/build_social.py`, `scripts/tennis/build.py`, `scripts/sports/build.py`).
4. Check `dashboard/brand.html` and spot-check one dense page in the new theme.

Never edit the dark values. If dark needs to change, it is a brand decision, not a build fix.
